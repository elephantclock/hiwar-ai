02 / Turn logic

Four paths through a conversation

Select a scenario. These sequences map to frames and handlers in natural.py.

Path A · default

Hear, decide, stream, speak.

VAD supplies acoustic evidence; Smart Turn decides the utterance is complete. A short filler may be spoken while Ollama produces its first token.

  1. Capture PCM audiotransport.input()
  2. Emit interim and final transcript framesWhisperSTTServiceMLX
  3. Close the user turn semanticallySilero + Smart Turn v3
  4. Optionally queue “hmm” or “let’s see”BotBackchannelFrame
  5. Stream assistant tokens into TTSOllama → Kokoro/Orpheus
  6. Play speech and commit assistant contextoutput → assistant aggregator
Path B · barge-in

Real speech wins; stray “yeah” does not.

At least two recognized words are required to start an interrupting turn. Known short acknowledgments and laughter are converted to non-conversational backchannel frames while the bot speaks.

  1. Bot emits speaking-state frameBotStartedSpeakingFrame
  2. User begins talking over outputVAD detects voice
  3. Filter checks acknowledgment vocabularyexact + laughter patterns
  4. “mm-hmm” becomes a backchanneldoes not enter LLM context
  5. Two or more real words start a new turnMinWords...Strategy
  6. Pipeline interruption cancels current responsePipecat frame semantics
Path C · rapport

Signal attention without polluting memory.

During a sufficiently long user turn, the companion may inject a quiet acknowledgment. It is spoken, but it is not stored as an assistant response and is not interruptible.

  1. Track the beginning of user speechVADUserStarted...
  2. Accumulate recognized word countinterim or final frames
  3. Require ≥ 3.5 seconds and ≥ 14 wordsplus 9-second cooldown
  4. Apply 60% probability gateavoid repetitive behavior
  5. Choose “mm-hmm”, “uh-huh”, “right”, or “hmm”random selection
  6. Emit as BotBackchannelFramespoken, not added to history
Path D · tool call

Keep conversation fast; move hard thinking aside.

The chat model handles dialogue. For calculation, research, or multi-step reasoning, the system prompt tells it to call a single local tool backed by a larger Ollama model.

  1. Chat model identifies a complex tasksystem prompt policy
  2. Call ask_backend with a precise taskPipecat tool schema
  3. Async Ollama client invokes backend modelseparate system instruction
  4. Backend returns { answer }tool result callback
  5. Chat model compresses answer for speechone to three sentences
  6. TTS speaks the final conversational answersame output path

06 / Boundaries

What this PoC is—and is not

The local architecture proves conversational behavior. A production call-center deployment needs additional media, safety, and operational layers.

Current gap

No echo cancellation

The local transport can re-capture speaker output. Use headphones; production needs AEC and noise suppression.

PoC boundary

No telephony gateway

This path uses local PyAudio devices, not SIP, PSTN, WebRTC, Twilio, or carrier infrastructure.

Current gap

No durable observability

Loguru emits runtime logs, but there are no persisted traces, latency histograms, recordings, or quality dashboards.

Production risk

Prompt-only tool policy

Delegation is model-selected and the backend has no external fact source. Add authorization, validation, timeouts, and audited business tools.

PoC boundary

English recognition fixed

The STT service sets Language.EN. Multilingual and code-switching behavior are outside this headless path.

Design choice

Emotion is indirect

Kokoro receives punctuation and prompt-shaped text. Orpheus is the intended richer emotional path, but needs a separate local server.
