System architecture

Audio in → action → expressive audio out

The customer speaks through a browser. A Hiwar realtime gateway detects turns and sends completed speech to hosted Whisper. The transcript passes to a conversation agent, which can use mock business tools and selects an emotional tone. Orpheus converts the response into expressive English speech that returns to the browser. Local voice detection can interrupt playback immediately.

Decision 01 · interaction model

Realtime turn-based, not native full duplex

The browser captures continuously, but the selected Whisper endpoint receives a completed utterance file. Fast endpointing, streamed agent text, sentence-level synthesis and immediate cancellation create the call-like experience.

Decision 02 · trust boundary

All provider access goes through the server

The browser never receives a Groq key. It holds only a short-lived Hiwar session token and communicates with the same-origin gateway over one WebSocket.

Decision 03 · provider isolation

Speech, reasoning and voice are adapters

Application interfaces isolate Groq-specific payloads. Local Whisper, a different chat model or local TTS can replace a provider without changing the browser protocol or session state machine.

Decision 04 · PoC persistence

Session memory only; no raw audio retained

Conversation state lives in one backend process and disappears when the call ends. Structured latency events may be logged; raw audio and transcripts are off by default.

What makes it feel realtime

Three control loops run around the model calls

Local loop · immediate

Barge-in

The browser detects new customer speech, stops audio playback immediately and tells the gateway to cancel the current agent turn.

voice detected→stop playback→cancel turn
Conversation loop · contextual

Emotion selection

The agent chooses a restrained service tone from the caller's words and context. It responds calmly to anger rather than imitating it.

sentiment→tone policy→voice direction
Speech loop · progressive

Sentence streaming

The agent writes concise sentences. Each completed sentence moves to speech while the next sentence is still being prepared.

text chunk→speech→queued audio

Session state and cancellation

One actor owns each connected browser call

LISTENING

Accept PCM frames; maintain VAD pre-roll.

ENDPOINTING

Silence closes and freezes one utterance.

TRANSCRIBING

Encode an in-memory WAV and call STT.

THINKING

Run agent loop against transcript and history.

TOOL_RUNNING

Validate and execute allow-listed functions.

SYNTHESIZING

Convert safe sentence chunks into WAV.

SPEAKING

Browser drains its scheduled playback queue.

Interrupt edge

Caller speech during THINKING, SYNTHESIZING or SPEAKING increments turn_epoch, cancels provider tasks, clears scheduled audio and returns the session to LISTENING. Every outbound event carries its epoch; browser and server both discard stale epochs.

Concurrency invariant: exactly one turn epoch may emit transcript, text or audio events. Cancellation is correctness logic—not a UI enhancement. Provider calls that cannot be cancelled may finish in the background, but their output is ignored.

Media pipeline

Capture, endpoint and playback without blocking the UI

1. Browser capture

  • Request mono microphone audio with echo cancellation, noise suppression and automatic gain control.
  • Use an AudioWorklet, not the main thread, to collect float samples.
  • Resample the actual device rate—commonly 48 kHz—to 16 kHz mono PCM16.
  • Batch 20 ms frames: 320 samples or 640 bytes per WebSocket binary message.

2. Endpointing

  • Run lightweight VAD locally so playback can stop without a network round trip.
  • Keep roughly 200 ms of pre-roll to avoid clipping initial consonants.
  • Start after sustained speech; close after configurable silence rather than a fixed recording button.
  • Cap an utterance at 30 seconds and reject empty or near-silent turns.

3. Output playback

  • Decode returned WAV chunks and schedule them against AudioContext.currentTime.
  • Hold every active AudioBufferSourceNode so barge-in can call stop().
  • Maintain a small queue, never an unbounded buffer; drop stale epochs before decode.
  • Pause capture-derived VAD calibration while output begins, but continue detecting real caller speech.

Echo safeguard: browser echo cancellation is requested, not guaranteed. Require a short run of confident speech before interrupting, test speakers and headphones separately, and expose the effective track settings in the debug panel.

Backend runtime

FastAPI reference decomposition

Connection boundary

Session API

Creates sessions, verifies short-lived tokens and upgrades the stream route to WebSocket. It never contains model logic.

Per-call owner

SessionActor

Owns state, history, turn epoch, task group, buffers and the single serialized outbound queue.

Media ingress

AudioIngress

Checks frame order and size, maintains pre-roll, creates an in-memory WAV and emits a closed utterance.

Orchestration

TurnCoordinator

Runs STT → agent/tool loop → sentence chunker → TTS while enforcing cancellation and time budgets.

Business boundary

ToolRegistry

Allow-lists functions, validates arguments and results, applies timeouts and separates reads from confirmed writes.

External boundary

Provider adapters

Implement stable transcribe(), stream_reply() and synthesize() interfaces around hosted APIs.

Output safety

SentenceAssembler

Builds speakable chunks under 200 characters without splitting amounts, identifiers or abbreviations.

Telemetry

EventSink

Emits structured stage timings and counters keyed by session and turn, excluding raw audio by default.

Demo data

MockCRM

Deterministic local order fixtures make tool results repeatable for tests and demonstrations.

Backpressure: cap each session's inbound frame queue. When the queue is full, close the socket with an application-specific code instead of accumulating latency. All server writes pass through one outbound task to preserve JSON/binary ordering.

Agent, tools and prompt boundary

The model proposes; application code authorizes and executes

Agent loop

  1. Send the transcript, compact conversation history and JSON schemas for allowed tools.
  2. If the model returns tool_calls, parse arguments as untrusted input and validate them against the tool schema.
  3. Execute the local function with a per-tool timeout and an idempotency key derived from session, turn and call ID.
  4. Append the bounded tool result using the matching tool_call_id, then ask the model for the caller-facing answer.
  5. Stop after two tool iterations; return a controlled escalation message rather than looping indefinitely.

Voice prompt contract

  • Speak in short, natural sentences; never read JSON, URLs or internal status names aloud.
  • Acknowledge before slow tools: “Let me check that for you.”
  • Never claim an action succeeded until its tool result confirms success.
  • Ask for one missing field at a time; repeat sensitive identifiers back only when necessary.
  • Remain calm and respectful; do not mirror anger, sarcasm or abusive language.

One customer turn

The event sequence behind a natural reply

  1. Listen

    The browser captures mono audio while local voice detection tracks speech and silence.

    Browser

  2. Close the turn

    A short silence marks the end of the utterance. The gateway packages only that turn for recognition.

    Hiwar gateway

  3. Understand

    Whisper returns the caller's words; the transcript appears in the call interface.

    Speech model

  4. Reason and act

    The conversation agent considers history, calls lookup_order when needed and produces structured tone plus text.

    Agent + tools

  5. Speak

    Short reply chunks are synthesized with directions such as [warm] or [calm and apologetic].

    Voice model

  6. Yield when interrupted

    New customer speech clears queued audio and starts a fresh turn without waiting for the agent to finish.

Failure handling and observability

Degrade visibly, recover safely, measure every stage

FailureApplication responseCaller experience
Microphone denied or unavailableDo not create a session; show browser-specific remediation.No fake connected state.
WebSocket interruptedStop capture/playback, cancel the server session and offer a fresh call. Do not replay buffered speech after reconnect.“Connection lost—reconnect to continue.”
STT timeout or empty transcriptRetry once only for transient provider failure; otherwise keep history unchanged.“I didn’t catch that. Could you say it again?”
Invalid tool callReject arguments, record a validation event and allow one model repair attempt.No internal error details; ask a clarifying question if repair fails.
Tool timeoutReturn a typed timeout result to the agent; never invent business data.Explain that the system cannot be checked and offer escalation.
TTS failureCancel remaining synthesis and retain the generated text response.Show the response as text with a “voice unavailable” status.
Provider rate limitRespect Retry-After; trip a short circuit breaker after repeated 429s.End or pause the demo clearly—never spin silently.
Late output after barge-inDiscard on epoch mismatch at both server enqueue and browser receive.No stale sentence plays over the next turn.

Local browser rule: microphone capture works on secure contexts and on localhost. Serve the browser and API from one origin during development to avoid unnecessary CORS and credential complexity.

Automated verification

  • Unit-test resampling, WAV encoding, sentence boundaries, tone mapping and epoch rejection.
  • Use fake provider adapters to deterministically test tool calls, timeouts and cancellation races.
  • Replay fixed WAV fixtures for silence, clipped speech, order numbers and background noise.
  • Run 100 forced barge-ins at different response stages and assert zero stale playback.
  • Keep golden scenario assertions on tool result and final application state—not exact model wording.

Implementation order

  1. Push-to-talk vertical slice with transcript, reply and WAV playback.
  2. AudioWorklet capture, VAD endpointing and WebSocket protocol.
  3. Session actor, epoch cancellation and playback queue.
  4. Mock CRM tool loop and explicit write confirmation.
  5. Tone controller, sentence-level TTS and live status UI.
  6. Failure injection, telemetry and scenario evaluation.

Deployment boundary

What stays local and what leaves the application

Inside the Hiwar PoC

API credentials, session state, mock customer records, tool permissions, cancellation logic, transcript display and latency measurements remain in the browser or local server.

Sent to hosted model APIs

Caller audio is sent for speech recognition. Transcript and conversation context are sent for reasoning. Approved reply text and its tone direction are sent for voice generation.

PoC boundary: free-tier APIs are appropriate for demonstration, not a production contact centre. They provide no commitment to availability, capacity or UAE/KSA data residency. Production deployment needs contracted services, retention controls and measured regional performance.
